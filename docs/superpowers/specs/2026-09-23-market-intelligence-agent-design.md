# Market Intelligence Agent 设计说明

## 目标与边界

面向企业经营、战略和产品团队，用户输入一个行业、研究问题及 2–4 家竞品后，工作台收集公开网页证据，生成可追溯的竞品与行业简报，标出冲突和缺口，并允许后续重跑查看变化。首个完整演示主题为新能源汽车。它是研究辅助工具，不自动给出投资建议，也不把搜索摘要当成已经核验的网页正文。

本项目以参与共同开发的 Folio 代码与 Git 历史为基础。个人新增创作是企业研究领域模型、公开网页检索工作流、证据核验规则、报告与差异展示、对应测试及演示材料。Folio 原有的股票研究、17 个筛选任务、8 套投资策略和 86 个基准案例不计入新增成果。公开仓库可以独立命名为 `market-intelligence-agent`，但保留原有贡献历史，在 README 中准确说明与 Folio 及共同贡献者的关系；不将继承代码宣称为个人独自完成。发布前确认已有的公开使用授权覆盖代码和资源，不自行给继承代码增加新的统一许可证。

## 用户流程

1. 用户选择新能源汽车示例，或填写行业、问题、竞品和时间范围。
2. 选择“示例数据”或“实时检索”。实时模式使用用户提供的 Brave Search API key；无 key 时给出明确配置指引，不静默回退为实时结论。
3. 系统按行业动态、竞品产品、定价/渠道、风险四类检索公开网页。每条证据保留标题、URL、来源、检索时间、摘要及检索查询；摘要明确标记为“搜索结果摘要，未核验正文”。同一 URL 去重，缺失 URL 的结果不可作为引证。
4. 报告按“关键结论—证据—反证/冲突—尚未确认—建议核查动作”组织。只从已保存证据建立引证，不能输出无证据的事实性断言；资料不足时产生部分报告并说明缺口。
5. 保存报告及输入快照。相同研究主题再次运行后，对比两次报告的新增/消失证据、结论变化与仍未解决的冲突。示例与实时报告始终有醒目标记，不互相混同。

## 架构

- 在 `packages/shared` 增加独立的 business-research 领域，使用 `industry/topic/competitors` 标识研究，不复用仅接受证券代码的 `ResearchService.start(symbol)`。
- 领域层定义输入、来源、证据、结论、报告、运行状态与差异的稳定类型。以纯函数验证输入、归一化检索结果、检查引证并计算差异，便于确定性测试。
- 主进程负责 Brave 适配器、凭证读取、运行预算/取消、持久化及 IPC。渲染进程只获得经过筛选的结果，不接触 API key、任意文件路径或原始 IPC 能力。URL 只允许 `https:` 公网地址；对搜索结果文本按不可信材料处理，限制长度，避免提示注入被当成系统指令。
- React 工作区展示输入表单、模式/运行状态、证据列表、报告、冲突和重跑差异。保留 Folio 现有投资研究入口，不修改其语义。
- 首版复用 Folio 已有模型连接和持久化惯例，但新增的结论检查不依赖模型自身声称“已核验”；模型不可用时保留可查看的证据与明确失败/部分状态，不制造合成结论。

## 运行状态与失败处理

运行经历 queued → searching → synthesizing → completed/partial/failed/cancelled。每个来源和引证有稳定 ID。缺少 API key、限流、网络超时、空结果和单类检索失败应可区分；取消不继续发请求。不会将示例数据作为实时检索的替身。报告与状态在重启后仍可查看；失败运行不覆盖上次成功报告。

## 验收与发布

- 单元测试覆盖输入边界、去重、URL/摘要安全处理、无证据结论拦截、部分失败与报告差异。
- 集成测试覆盖示例数据与模拟 Brave 返回的完整运行，包括取消、重试/限流及保存后读取。
- 端到端演示至少展示一次新能源汽车示例报告、证据跳转、刷新后的持久化和一次重跑差异；实时路径仅在实际配置 key 并完成运行后才标为已验证。
- 运行仓库的类型检查、单元测试和相关 UI/E2E 测试；记录命令与结果。README 包含真实功能边界、配置方法、演示截图、来源/贡献说明和未完成项。
- 完成验证后创建并推送到用户个人 GitHub 的独立仓库，不向 Folio 上游提交此项目的 PR。

## 本阶段范围

先交付上述可运行的纵向切片，不把 CRM 接入、企业内网搜索、自动监控通知、多 Agent 编排、付费数据源或投资判断纳入首版。这样可以先证明一份报告从公开证据到持久化对比的完整链路。
