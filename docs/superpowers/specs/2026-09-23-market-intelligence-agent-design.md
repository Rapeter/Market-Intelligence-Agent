# Market Intelligence Agent 设计说明

## 目标与边界

面向企业经营、战略和产品团队，用户输入一个行业、研究问题及 2–4 家竞品后，Agent 根据检索观察动态选择下一步调查动作，收集公开网页证据，生成可追溯的竞品与行业简报，标出冲突和缺口，并允许后续重跑查看变化。用户还可订阅主题，在应用运行期间自动发现新信息并触发重跑。首个完整演示主题为新能源汽车。它是研究辅助工具，不自动给出投资建议，也不把搜索摘要当成已经核验的网页正文。

本项目以参与共同开发的 Folio 代码与 Git 历史为基础。个人新增创作是企业研究领域模型、动态 Agent 工作流、公开网页检索、证据核验规则、报告与差异展示、对应测试及演示材料。Folio 原有的股票研究、17 个筛选任务、8 套投资策略和 86 个基准案例不计入新增成果。公开仓库可以独立命名为 `market-intelligence-agent`，但保留原有贡献历史，在 README 中准确说明与 Folio 及共同贡献者的关系；不将继承代码宣称为个人独自完成。发布前确认已有的公开使用授权覆盖代码和资源，不自行给继承代码增加新的统一许可证。

资料边界是**公开可访问的信息**：公开网页、企业官网与公开披露文件、公开评论/反馈。系统可把网页中的日期、产品、公开价格等字段抽取为带来源 URL 的结构化观察，但不承诺独立企业数据服务或内部数据接入。公开反馈只是有偏样本的线索，不等同于完整或代表性的客户调研；简历及 README 应使用“公开客户反馈观察”等准确措辞。

## 用户流程

1. 用户选择新能源汽车示例，或填写行业、问题、竞品和时间范围。
2. 选择“示例数据”或“实时检索”。实时模式使用用户提供的 Brave Search API key；无 key 时给出明确配置指引，不静默回退为实时结论。
3. Agent 根据研究目标先选择检索方向；每轮观察搜索结果后，再决定检索其他角度、细化查询、打开已发现的公开来源，或在证据足够/预算耗尽时停止。每条证据保留标题、URL、来源、检索时间、摘要及检索查询；只从搜索摘要获得的信息标记为“搜索结果摘要，未核验正文”。同一 URL 去重，缺失 URL 的结果不可作为引证。
4. 报告按“关键结论—证据—反证/冲突—尚未确认—建议核查动作”组织。只从已保存证据建立引证，不能输出无证据的事实性断言；资料不足时产生部分报告并说明缺口。
5. 保存报告及输入快照。相同研究主题再次运行后，对比两次报告的新增/消失证据、结论变化与仍未解决的冲突。示例与实时报告始终有醒目标记，不互相混同。
6. 用户可订阅已保存的主题。应用运行期间按用户设置的间隔（默认 24 小时，最短 1 小时）执行轻量公开检索；发现新的相关来源或已知来源的实质更新时，最多触发一次同主题研究。无变化、重复链接、不相关结果或检索失败时不触发，并显示检查时间与原因。应用关闭期间不保证监控；下次启动时补做一次已到期检查。

## 架构

- 在 `packages/shared` 增加独立的 business-research 领域，使用 `industry/topic/competitors` 标识研究，不复用仅接受证券代码的 `ResearchService.start(symbol)`。
- 领域层定义输入、来源、证据、结论、报告、运行状态与差异的稳定类型。以纯函数验证输入、归一化检索结果、检查引证并计算差异，便于确定性测试。Core 的决策只允许 `search_web`、`open_source`、`finish` 三种动作；Runtime 负责预算、取消、重试、顺序事件和持久化。模型/工具接口位于端口之后，不将 SDK 对象暴露为业务契约。
- 主进程负责 Brave 适配器、凭证读取、运行预算/取消、持久化及 IPC。渲染进程只获得经过筛选的结果，不接触 API key、任意文件路径或原始 IPC 能力。URL 只允许 `https:` 公网地址；对搜索结果文本按不可信材料处理，限制长度，避免提示注入被当成系统指令。
- 公开网页抽取的字段必须附带原文片段、来源 URL、检索时间与抽取状态；未能核对原文的字段只保留为搜索摘要线索。报告对这两类证据分级展示，不能把摘要升级为已核实事实。
- `open_source` 只能打开本次搜索发现的公网 URL；重新校验重定向目标与解析地址，限制响应大小与读取时间，抽取纯文本，不执行网页脚本。检索/网页正文中的任何指令都只是数据。一次运行限制迭代次数、工具次数、检索结果长度和总时长；无进展连续迭代必须失败而非空转。
- 新增独立的主题订阅与检查记录，不把企业主题塞入 Folio 的证券自动化规则。检查器复用主进程调度/持久化惯例，但先用固定的主题探针查询完成低成本发现；按规范化 URL、标题/摘要指纹、已知来源正文摘要与企业/主题匹配判断变化，再将真正的新线索交给 Agent 深入研究。每个订阅与线索指纹只允许一个未完成的触发运行；记录触发、跳过或失败原因。关闭订阅立即停止后续检查，不取消已开始的研究。
- React 工作区展示输入表单、模式/运行状态、证据列表、报告、冲突和重跑差异。保留 Folio 现有投资研究入口，不修改其语义。
- 首版复用 Folio 已有模型连接和持久化惯例，但新增的结论检查不依赖模型自身声称“已核验”；模型不可用时保留可查看的证据与明确失败/部分状态，不制造合成结论。

## 可核验的首版规模

首版设计目标为 **6 类企业研究任务、3 套研究策略、24 个任务级评测案例**，不是继承 Folio 原有的 17/8/86，也不是在未实现前可对外宣称的数字。这些数量不单独构成发布门槛：发布时只陈述实际完成并通过验证的数量。

- 六类任务：行业格局扫描、竞品产品比较、价格与渠道观察、公开客户反馈信号、政策与技术风险、证据冲突/变化核查。任务有不同输入、期望证据和结束条件；公开评论只能作为有偏样本信号，不称为代表性的客户调研。
- 三套策略：行业全景、竞品深挖、变化与风险追踪。策略定义初始关注维度和预算，不写死完整工具顺序；Agent 可以根据观察改选下一任务或补查来源。用户可从执行记录看到为什么转向。
- 二十四个评测案例：六个基础任务案例、四个资料缺失分支、三个来源冲突分支、三个工具失败/超时分支、四个引证安全/提示注入分支、四个自动发现/触发分支。前二十例是研究运行案例，每例有输入、固定来源响应、允许的下一动作、终止状态和引证断言。触发四例分别覆盖新相关来源、已知来源实质更新、重复或无变化、无关结果；前两例应创建研究运行，后两例不得创建运行，各有预期检查结果及触发次数。检索故障由工具失败分支覆盖。案例是可执行的 Agent 场景，不拿普通单元测试凑数。

## 运行状态与失败处理

运行经历 queued → planning → gathering → synthesizing → completed/partial/failed/cancelled。每一轮持久化模型决策、工具参数的安全摘要、工具结果状态、观察及停止原因，事件序号单调递增；秘钥和未清洗网页内容不进入轨迹。每个来源和引证有稳定 ID。缺少 API key、限流、网络超时、空结果和单类检索失败应可区分；取消不继续发请求。不会将示例数据作为实时检索的替身。报告与状态在重启后仍可查看；失败运行不覆盖上次成功报告。

## 验收与发布

- 单元测试覆盖输入边界、去重、URL/摘要安全处理、无证据结论拦截、部分失败与报告差异。
- 集成测试覆盖示例数据与模拟 Brave 返回的完整运行，包括取消、重试/限流及保存后读取。
- 动态决策验收使用至少两组仅证据不同的同题输入，要求后续工具选择或查询方向确实不同；用可回放轨迹验证决策 → 工具 → 观察 → 下一决策，检查预算、无进展、取消和证据冲突分支。脚本模型的确定性测试与真实模型运行分开记录；只有真实模型运行完成后才称为“真实 Agent 动态决策已验证”。
- 自动发现验收使用可控时钟与两次公开来源快照，检查到期后启动、变化指纹去重、重启后补查、订阅关闭、并发触发合并，以及“无实质变化/无关/失败不触发”。真实模式需实际完成一次新信息触发的研究才能宣称自动发现的线上路径已验证；否则只标记夹具验证。
- 端到端演示至少展示一次新能源汽车示例报告、证据跳转、刷新后的持久化和一次重跑差异；实时路径仅在实际配置 key 并完成运行后才标为已验证。
- 运行仓库的类型检查、单元测试和相关 UI/E2E 测试；记录命令与结果。README 包含真实功能边界、配置方法、演示截图、来源/贡献说明和未完成项。
- 完成验证后创建并推送到用户个人 GitHub 的独立仓库，不向 Folio 上游提交此项目的 PR。

### 评测指标、统计口径与通过条件

24 个版本化的固定案例各执行一次，其中预期产生 22 次研究运行、2 次不触发检查。报告同时列出通过数、失败数、样本数、模型/数据源版本与运行日期；不得只公布百分比或剔除失败样本。固定案例使用可控时钟和来源快照，真实网络/模型运行单列，不与夹具结果合并。下列比例在分母为零时记为“不适用”，不能写成 100%。下表是宣称完整 6/3/24 目标时的验收要求；若先发布范围更小的版本，必须公布实际数量和未通过项。

| 指标 | 统计口径 | 完整目标的验收 |
| --- | --- | --- |
| 任务完成度 | 六个正常案例中，状态为 `completed` 且包含必需章节、至少一条有效引证的案例数 / 6。另报 24 个案例的预期结果命中数 / 24：研究案例比较运行终态，触发案例比较 `triggered`/`not_triggered`；预期 `partial` 的案例被错误标成 `completed` 算失败。 | 正常任务 6/6；预期结果 24/24。三套策略在六个正常案例中各至少覆盖两次。 |
| 工具选择正确率 | 处于人工标注决策检查点时，所选动作和参数同时属于该检查点允许集合的次数 / 全部已标注决策检查点次数；非法工具、越权 URL、无关查询均算错，不按整次运行掩盖错误步骤。 | 固定案例为 100%；真实模型的两组对照输入中，至少两组都出现符合证据差异的后续决策分叉，且非法工具调用为 0。 |
| 证据有效率与覆盖率 | 有效引证数 / 报告引证总数：ID 存在、URL 合法、来源类型标签正确且在案例标注中支持对应论断才算有效。另报有有效引证的事实性论断数 / 事实性论断总数；没有论断时不适用。搜索摘要不能标为已核验正文。 | 两项在固定案例均为 100%；三个冲突案例中的预期冲突均被标记且没有被写成单方确定事实。 |
| 执行时延 | 从持久化 `run_started` 到终态的单次耗时，按预期产生的 22 次研究运行报告中位数 p50 与最近秩 p95（升序第 `ceil(0.95 × N)` 个值），并分别列出成功、部分、失败、取消的数量。未按预期启动的运行仍记为案例失败，不伪造时延样本；工具耗时另报 p95。 | 无网络的固定案例整次运行 p95 不超过 30 秒、单次不超过 60 秒；真实运行逐次记录，默认总预算 180 秒，超预算必须得到明确终态而非悬挂。 |
| 故障恢复率 | 三个注入工具失败/超时案例中，按预期重试、降级为 `partial` 或明确失败且不重复写入证据的案例数 / 3。不可恢复的认证错误不得伪装成可重试。 | 3/3；取消后新增工具调用为 0，重启读取的报告与事件顺序一致。 |
| 自动触发准确率 | 四个触发案例中，两例为应触发（新相关来源、已知来源实质更新），两例为不应触发（重复/无变化、无关结果）。精确率 = 正确触发数 / 全部触发数；召回率 = 正确触发数 / 两个应触发案例。每个线索指纹重复触发次数单列。 | 精确率 2/2、召回率 2/2；同一指纹最多触发一次，模拟时钟到期后的下一次检查内开始运行。 |

若指标未达到门槛，保留失败记录、原因和修复后的重跑结果；不得把设计目标或夹具成绩写成真实线上效果。公开项目展示中说明简历可据实写“公开信息与客户反馈信号研究”，不宣称代表性客户调研或独立企业结构化数据源。

## 本阶段范围

先交付上述可运行的纵向切片，不把 CRM 接入、企业内网搜索、应用关闭后的常驻监控、自动外发通知、多 Agent 编排、付费企业数据源或投资判断纳入首版。这样可以先证明公开证据 → Agent 决策 → 报告 → 新信息触发 → 持久化对比的完整链路。
